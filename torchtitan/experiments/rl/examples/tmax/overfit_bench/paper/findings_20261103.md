# Findings, 2026-11-02/03 (GB300, teacher rewriter)

Setup: one task per job on one 4 x GB300 host, Qwen3.5-9B student, pure RL with 0/1 reward and
`drop_zero_std`, groups of 12. A teacher (a codex agent) writes easier versions of the task into a
pool; groups draw versions by weight; the student is examined on the original every 5 steps
(readout, 16 attempts). Lenient bar: a training group on the original passes at least half its
attempts, or one readout reaches 3/16 (4/16 before 2026-11-03 01:15). Two-stage bar: 13/64 on a
64-attempt confirm. Base rates are the base model's passes over ~75 step-0 attempts.

## 2. A teacher told to show the tests' convention shipped the grading material

The teacher reads the original's `tests/` and `solution/` by design (README, "Two loops"); the
student sees only a version's instruction and environment. On 2026-11-03 01:30 (068e24a0) the
teacher's prompt gained a section from earlier runs: find the check the original fails on, show
the convention the tests expect and then take it away, ship checkers early.

- model-extraction-relu-logits's teacher restarted on it at 01:31. Its next round (02:22) wrote
  `original_checker_fix`: the original verifier, with its grading network, as `/app/check.py`.
  Round 10 (03:10) wrote `seed_hint_original`: the grading seed and draw (`np.random.seed(5)`,
  `randn(30, 10) * 0.3`) in the instruction. Its stated reasons echo the prompt ("exposing that
  check during the attempt", "teach the exact hidden replacement convention"). Rounds 1-4, on the
  earlier prompt, wrote no such version. Both versions trained the student (one group 8/12), so
  the solve that followed (original groups 6/12) is void.
- An audit of every version behind the solved rows (7 tasks): grading material only in
  model-extraction (2 versions). Hidden-check specifics in prose (thresholds, the reference's
  convention or arguments, edge cases the hidden tests probe) in extract-elf, mteb-retrieve,
  sanitize-git-repo and model-extraction (tolerance `1e-4`, also in versions written before
  068e24a0).
- A line-level scan of all 550 versions on disk found versions carrying the original's test files
  as checkers in older runs as well (torch-tensor-parallelism, torch-pipeline-parallelism,
  filter-js-from-html, llm-inference-batching-scheduler, 11-01/11-02, none solved): the hazard
  predates 068e24a0; the prompt turned it into handing over the answer.
- Fix (9d033b16, a25621c8): the prompt forbids putting the original's tests, verifier, hidden data,
  seeds, reference solution or hidden-check specifics where the student sees them; `validate()`
  refuses a version whose instruction or environment carries lines of the original's tests or
  solution; a restarted teacher retires such versions already in the pool (7 retired across 4
  running jobs).
- After the fix: 23 new versions across 8 jobs, none refused by the line check, and an audit of all
  23 found no grading material and no hidden-check specifics (2 install-windows versions borderline:
  a launch-option template matching the reference's option layout with the values left as
  placeholders).
- Separately, naming tasks and an earlier run's diagnosis in the teacher's prompt hands a teacher
  on that task conclusions from outside its run; those findings moved to the README (f467648c), and
  the torch-tensor rerun started under them is not comparable.

## 4. The original's draw share

- Giving the original half the draws once it passes in a training group helps (sqlite at 1/2: next
  original group 4/11 against 1/12 at 1/8).
- A share above the floor before the original has passed starves training: polyglot-rust-c's
  teacher set the original to 83% of draws, the original went 1/404, every group ended 0/12 and the
  run sat at step 0 for 3 h. From 093dd27c a teacher may raise the share only after the original
  has passed; polyglot then moved (original groups up to 4/12 by step ~20).

## 5. Throughput

- Generation is 91-97% of an attempt's time. Default compile with CUDA graphs to batch 2048 gave
  +32% decode throughput (1115 -> 1475 tok/s at 96 agents); TRITON_ATTN and MTP did not help under
  load.
- Some tasks are bound by the sandbox, not the GPU: train-fasttext ran ~8 generations in flight
  against 90-145 on other jobs, ~1 h per attempt (model training in a 1-CPU sandbox, 18% flagged
  OOM), 6 steps in 3 h; install-windows-3.11 ~18 in flight, ~20 min per step.
- Rollout errors on a shared sandbox account: 0-12% of attempts per job errored, mostly
  `Total CPU limit exceeded` at sandbox creation; the group trains on what remains.
- 109 GB checkpoints written asynchronously at ~45 MB/s fall behind; a failed save no longer ends
  the run (bdc9bb26, 03369b70).
