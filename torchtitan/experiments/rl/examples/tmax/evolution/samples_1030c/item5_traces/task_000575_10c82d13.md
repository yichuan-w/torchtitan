## Primary-source research and pin

- https://raw.githubusercontent.com/containers/bubblewrap/v0.6.1/bwrap.xml — the `--new-session` documentation says it calls `setsid()`, disconnects the sandbox from the controlling terminal, and prevents the sandbox from injecting terminal input; without it, Bubblewrap recommends seccomp to disallow `TIOCSTI`.
- https://github.com/containers/bubblewrap/issues/740 — an operator reports a Bubblewrap-launched shell escaping back to the host shell after Ctrl-C and leaving terminal input/output confused; the reproducer uses `--new-session`, showing the real operational domain of terminal-session handling.
- https://github.com/containers/bubblewrap/archive/refs/tags/v0.6.1.tar.gz — the upstream repository's immutable v0.6.1 tag archive was fetched and measured as SHA-256 `2b21ee6d2bead1aaf7c35742e5e53b061ec6eb1644889a4379fda662b03e8121`.

The Dockerfile copies that fetched upstream tag archive, verifies that SHA-256, and confirms the installed Bubblewrap reports 0.6.1. This preserves the version already observed in the seed while pinning the actual upstream source artifact rather than relying only on a movable distribution build.

## Reproduced behavior

In the seed sandbox, `bwrap --version` reports 0.6.1. Running a shell with the requested options but no session isolation prints the same session ID as its host shell (`host sid 409`, sandbox sid `409`). Adding Bubblewrap's session-isolation option gives the sandbox its own session (`sandbox pid 607`, sid `607`). Thus the existing wrapper's mounts and network namespace do not isolate it from the caller's controlling terminal, and no error announces the missing control.

## Proposed change and new decision

Preserve all four original deliverables and add one security property to the existing wrapper: the sandboxed process must be unable to inject input into the invoking terminal. This is core Bubblewrap configuration, not an extra artifact. The student must investigate process/terminal isolation and choose Bubblewrap's terminal-session control (or a valid seccomp-based equivalent) rather than merely transcribing the listed mounts. That is one modest step beyond the attempts' demonstrated ability to compose and test a Bubblewrap command.

The changed scratch check will reject the observed three-flag wrapper because it retains the caller's session. A legal implementation using Bubblewrap's new-session facility remains accepted.
